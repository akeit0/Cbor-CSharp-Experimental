# Typed serializer architecture

The product is a CBOR serializer. Primitive parsing and structural validation support typed decoding, streaming boundaries, and version-unknown data. They do not replace object serialization.

## Formatter and resolver contract

Factories return fresh uninitialized instances owned by one resolver graph. They must not share initialized instances between resolvers. Initialize only acquires dependencies; recursive children may still be initializing.

The primary contract follows [MessagePack-CSharp v4's buffer-pair formatter](https://github.com/MessagePack-CSharp/MessagePack-CSharp/blob/a9057be29b0621d56a4312f79172e759bbb4e1de/src/MessagePack/IMessagePackFormatter.cs): ICborFormatter<TWriteBuffer, TReadBuffer, T> closes over both Foundation buffer types. Serialize and Deserialize are ordinary methods over those fixed types. Initialize acquires typed child formatters once from the complete resolver chain. Instances become immutable and thread-safe after initialization; they borrow buffers and contexts by reference and never dispose either. CBOR Deserialize returns a value; in-place population is not currently a contract.

CborFormatterFactory creates uninitialized instances through one generic CreateFormatter<TWriteBuffer, TReadBuffer>(Type valueType) contract on every target. NET9+ permits ref-struct buffer arguments; other assets use ordinary struct arguments. Generated, built-in, and custom factories serve caller-defined buffers through the same contract. There are no Type-based buffer dispatch tables, cross-target ABI adapters, reflection, MakeGenericType, assembly scanning, or dynamic code. Combine snapshots and flattens ordered factory chains; the first provider serving the requested buffer pair and value type wins.

CborFormatterResolver owns the initialized graph for each exact (write buffer, read buffer, CLR type) tuple. Warm lookup indexes an object array using a private generic type ID, then reinterprets a reference only after the matching typed instance was validated and published into that slot. Cold construction is serialized under one resolver lock. A created instance enters the pending graph before Initialize runs, so recursive dependencies receive the same in-progress instance. The resolver publishes the entire completed graph with a single copy-on-write array publication. Other threads cannot observe a partially initialized child. Initialization failures abandon the graph and remain retryable, including a dependency failure swallowed by a custom initializer. Missing types use a cached formatter that throws when used.

Generated models, enums, nullable wrappers, arrays, lists, dictionaries, and tagged wrappers store typed child formatter fields. Repeated nested instances and repeated operations reuse those fields. There is no operation-local formatter dictionary, pool rental, dependency resolution per object, or static formatter initialization cycle. Options take a factory and create an independent resolver over that factory followed by built-in scalars, so custom overrides apply throughout its graph. Initialized selections stay fixed for that resolver’s lifetime; changing provider behavior requires new options. Structural object keys bypass CLR integer overrides.

NET9+ owned entry points use Foundation ref-struct buffers; NET8 and .NET Standard assets use ordinary Compatible buffers. The factory resolves the exact pair, and a missing provider produces a cached formatter that fails when used. There is no automatic buffer fallback or retry. Borrowed write entry points pair the caller’s writer with the current tier’s span reader; borrowed read entry points pair the caller’s reader with that tier’s array writer. Formatters must serve the requested pair. Caller buffers are never reinterpreted or staged.

There is one paired formatter contract. CborFormatterResolver is sealed and accepts a factory; generated [CborFactory] roots derive directly from CborFormatterFactory. Single-type formatter contracts, formatter registries, collection-provider facades, resolver adapters, and cross-version loading fixtures are absent. Providers are compiled against the runtime asset used by their consumer; cross-target binary compatibility is not promised. New custom formatters use the same creation and initialization path as generated and built-in formatters.

Context serialization methods require an initialized paired formatter. Nested values pass through these budget-checking overloads with their cached child fields; context APIs do not resolve dependencies. Nullable and enum wrappers delegate through SameItem because their underlying representation is the same wire token. Containers pair EnterContainer and ExitContainer in finally. Contexts carry immutable options and mutable per-call item, byte, declared-element, and depth budgets; they retain no formatter cache or pool storage.

## Wire contracts

| CLR shape | CBOR representation |
| --- | --- |
| Boolean | Simple false/true |
| Integral types | Integer; checked narrowing on read |
| CborInteger | Major type 0/1 with the full -2^64 through 2^64-1 range |
| CborSimpleValue | Simple numbers 0–23 or 32–255; null and undefined remain distinct |
| BigInteger | Major type 0/1, or standard tag 2/3 with an unsigned big-endian magnitude |
| CborTagged<T> | Tag number plus exactly one typed child; nested wrappers preserve tag chains |
| Half (NET8+ assets) | Preferred float width, canonical half NaN, preserved signed zero |
| Single/Double | Shortest exact float width; canonical half NaN; negative zero preserved |
| String | Strict UTF-8 text; null remains null |
| Byte array | Byte string; null remains null |
| Nullable value | Underlying wire item or null |
| Enum | Declared integral underlying type; unknown enum values preserved |
| Array/List | Array, or null |
| Dictionary | Map, or null |
| CborObject class/struct | Map with explicit nonnegative integer member keys |

Half and Single reads may round an in-range wider float, but reject finite values outside the target's range, including values just beyond an endpoint that a CLR cast rounds back to the endpoint. Infinity and NaN remain supported. Float formatters do not reinterpret integers or arbitrary tagged values as floats. Undefined is not a synonym for null. CborSimpleValue rejects reserved numbers 24–31, floating-point tokens, and break; its default is simple 0. CborInteger defaults to unsigned zero and exposes checked CLR conversions without narrowing its wire representation.

BigInteger follows [RFC 8949 sections 3.4.3 and 4.1](https://www.rfc-editor.org/rfc/rfc8949.html#section-3.4.3): tag 3 with magnitude n represents -1-n. Writers use major types 0/1 through their full unsigned argument limits, then tag 2/3 with no leading zero bytes. Readers accept those integers and bignum tags with definite or indefinite byte-string content, including empty magnitudes. Preferred policy additionally rejects unnecessary bignum tags and leading zeros. Structural scanning preserves arbitrary tags without imposing these typed semantics. Tag and content share item/depth/string limits; structural magnitude bytes bypass CLR byte-array overrides.

Modern and netstandard2.1 definite bignums decode from a borrowed contiguous window into owned BigInteger limbs; Foundation reassembles segmented windows when necessary. Writers preflight tag, header, and payload before using bounded stack space or cleared pooled bytes. The netstandard2.0 API requires signed little-endian intermediate arrays; its decoder creates one bounded sign-padded array. Chunked magnitudes use the bounded byte-string aggregator. Large negative magnitude conversion and adverse segmentation need broader allocation/timing evidence.

CborTagged<T> preserves an application-selected tag number and one typed child without asserting the tag's registered meaning. Closed wrappers participate in generated dependency graphs and retain child overrides. Bare null does not substitute for a tagged wrapper. The generator diagnoses Half roots when the referenced asset lacks Half support. Additional date/time, decimal, and UUID mappings still require separately specified interoperable contracts.

Writers emit definite lengths. Readers accept definite and indefinite strings/collections unless policy forbids them. Every text chunk must individually be valid UTF-8. Aggregation bounds the combined byte length before growing pooled storage; the pool is returned in finally and cleared. A constrained struct materializer specializes the shared chunk traversal for string versus byte-array results without object casts or an interface-typed strategy instance. This works on the .NET Standard tier as well as modern .NET.

Generated object writes sort member keys by integer value. This does not establish deterministic encoding for arbitrary nested dictionaries. Missing optional members receive default(T); Required means presence, not a non-null value requirement. Known duplicate keys fail. Unknown keys and values are traversed with the same policies and budgets, including malformed nested data. Unknown-key duplicates are not interpreted as object members.

New public instance slots must explicitly opt in with CborKey or opt out with CborIgnore; property overrides retain the inherited slot contract. Readonly members bind to accessible constructor parameters by name and CLR type; CborConstructor can select a constructor. Construction occurs after all entries and required-member checks pass. Keys are stable schema identities and must never be reassigned after removal.

Closed generic classes, structs, records, and types nested inside closed generic containers are generated for their concrete type arguments. Constructors and inherited members use Roslyn's substituted symbols; no runtime generic construction is needed. Recursive graphs may revisit the same closed type, and finite cycles that permute arguments are supported. Open generic roots are rejected. Dependency traversal is iterative and cancellation-aware. A generated factory accepts at most 4,096 distinct reachable types; each constructed type is bounded to 64 nesting levels and 4,096 components, preventing expanding generic dependencies or exponentially large type expressions from exhausting the compiler. These limits produce diagnostics, with no partial factory output.

Model inheritance flattens the selected CLR type's hierarchy into one map, sorted by integer key. Every model class in that hierarchy explicitly declares CborObject; abstract bases are permitted when generating a concrete derived type. Keys are unique across all inherited slots. A property override inherits its virtual slot's key and Required setting when it has no explicit contract attributes; an explicit override must preserve both. A keyed slot cannot be hidden by a new property, field, method, or static member, or removed with CborIgnore. Ignored virtual slots remain ignored unless explicitly opted into the derived contract. Members and accessors must be accessible from the generated factory, including members from external assemblies. Derived constructors bind inherited readonly members by their substituted names and types. Inheritance supplies the declared type's members; it does not introduce a subtype discriminator or polymorphic dispatch.

Constructor-bound members are not assigned again in the object initializer. C# required members must be initialized by that initializer or covered by a constructor marked SetsRequiredMembers; compiler requirements and CborKey.Required wire-presence requirements are separate contracts.

## Resource and ownership behavior

Formatter graphs allocate only during cold acquisition. Resolver tables retain initialized formatters for that resolver's lifetime. Warm root/child dispatch does not allocate formatter state per call; result objects, strings, BigInteger limbs, and Foundation buffer growth have their own allocation behavior. Changing a custom override requires a fresh graph rather than mutation of a published formatter.

Serializer reads process the input once, rather than validating an entire message and parsing it again. A bounded input length is checked before decoding. Declared collection counts share a message-wide child budget and cannot force allocations inconsistent with the available bytes or configured limits. Actual items, including unknown-member tokens and indefinite string chunks, share an item budget. Containers share a depth budget.

Typed reads inspect the initial byte and use specialized scalar/length decoders. Valid contiguous extended integers remain on that path; seams and invalid input enter cold helpers. Default context checks validate the token prefix without reconstructing a general header or decoding its argument again. Preferred encoding remains an explicit policy with numeric and floating-point checks. Unknown structural traversal uses the general decoder, with value-type scan limits and a scalar path that avoids allocating a traversal stack.

Text serialization computes strict UTF-8 byte length once before encoding. Built-in string and byte-array writers preflight the complete header plus payload against remaining encoded bytes before requesting output memory. Custom formatters can use CheckEncodedLength with the buffer's absolute position and planned bytes; the post-formatter byte check remains a backstop rather than rollback.

Dictionary deserialization rejects duplicate CLR keys and null keys. Built-in comparers use a per-process CSPRNG key and SipHash-2-4, avoiding predictable integer/string hash collision families across buffer tiers. Floating-point comparers normalize signed zeros and NaN representations consistently with CLR equality. Other key types require an explicit comparer; its equality and collision resistance are the caller's contract. SipHash is independently checked against all 64 author vectors.

.NET 8 and newer dictionary readers reserve an entry with one lookup, rejecting a duplicate before decoding its value. The dictionary remains private until successful return, so nested formatters cannot resize its entry storage while a managed value reference is in use. A failed value decode abandons the dictionary and context. .NET Standard assets retain ContainsKey/Add because their reference assemblies expose no safe entry-reference insertion API. The dedicated .NET 8 asset separates entry-reference capability from the .NET 9 boundary for ref-struct buffers; its Compatible buffers use the same single-probe dictionary path as newer assets.

Structural UTF-8 checks use the runtime ASCII validator on modern assets. Non-ASCII text uses bounded unaligned four-byte loads to check whole code points, including overlong, surrogate, and Unicode upper-bound restrictions; byte state is limited to tails and buffer seams. Compatibility assets use the same whole-code-point checks and four-byte ASCII skips. Loads stay within the supplied span, and endianness is explicit. State may cross buffer segments but never text chunk boundaries.

Public entry points own their Foundation buffer wrappers and operation contexts and complete them in finally. Caller-owned writers remain open. Borrowed-buffer overloads dispose their own context and do not dispose or flush the borrowed buffer. Deserialize requires exactly one item and rejects trailing bytes. Streaming writes can commit a prefix before failure; rollback belongs to the caller. A context is single-owner mutable state: pass it by ref, never copy or box it, and complete it after finishing or abandoning the operation. Custom formatters borrow the context and must not dispose it. Direct context callers must pair construction and disposal in try/finally; do not use a using local when it needs to be passed by ref. The packaged CBOR003 analyzer rejects ownership copies, boxing, readonly mutation, and unsafe return/property/collection shapes; runtime code and reflection still must honor ownership. Newer collection-expression syntax is checked through a runtime-bound syntax kind so the analyzer still loads on Roslyn 4.3 hosts.

## Evidence and remaining work

Generated contracts compile and run against netstandard2.0, netstandard2.1, net8.0, net9.0, and net10.0 assets. Tests cover fixed bytes, every sequence seam, one-byte/empty segmentation, truncation, mutable/immutable objects, records, structs, enums, recursive graphs, nested collections, required/duplicate/unknown members, shared budgets, concurrent immutable resolver use, and an independent System.Formats.Cbor object oracle. Compiler-driver tests exercise invalid contracts and edited generation inputs. The packed NuGet consumer uses generated mutable/immutable models; Windows Native AOT executes generated models, segmented data, and keyed dictionaries.

Unions, circular-reference preservation, and external formatter annotations remain incomplete. Broad semantic-tag built-ins, deterministic dictionary ordering/key-equivalence profiles, async outer streaming/cancellation, IDE fixes, shrinking/coverage-guided fuzzing, and comparable object benchmarks remain required for full serializer maturity. The project does not claim released MessagePack parity from these tests.

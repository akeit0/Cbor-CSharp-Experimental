# Remaining quality and performance gaps — 2026-10-02

| Priority | Open issue | Required evidence or work |
| --- | --- | --- |
| P2 | Operation resolution has a fixed cost on small messages: oldest-asset flat models add about 16 ns encode / 10 ns decode; default scalar reads add 1–2 ns. | Reduce context setup/cleanup and first-resolution costs while retaining operation-local custom choices, reentry safety, and unchanged allocations. See docs/benchmarks/operation-resolution.md for the measured tradeoff. |
| P2 | .NET Standard dictionary readers perform `ContainsKey` and `Add`, hashing valid keys twice after the first insertion. | Compatibility measurements and a scoped built-in hash-reuse prototype are recorded in docs/benchmarks/operation-resolution.md. Hash reuse gave mixed preliminary results and was rejected. Dedicated .NET 8+ assets now use supported single-probe insertion; the residual gap is the .NET Standard fallback. Safe public entry-reference insertion is unavailable in these reference assemblies; find an approach that preserves comparer identity, duplicate rejection before value decoding, failure behavior, and short-key performance. |
| P2 | Chunked strings validate each chunk and then decode the aggregate, with pooled growth and a final copy for byte arrays. Malformed and highly fragmented text need broader timing evidence. | Evaluate aggregation and allocation strategies that preserve rejection of malformed chunk boundaries; measure malformed input and adverse segmentation alongside normal text. |
| P2 | Generator coverage lacks measurements of cached incremental steps after unrelated edits and cancellation on large graphs. | Track incremental steps and compiler time for large/multiple resolvers; retain a compiler-host compatibility matrix. |
